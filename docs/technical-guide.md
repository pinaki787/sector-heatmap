## Architecture and responsibility

[web.py](../sector_heatmap/web.py) builds independent services and routes HTTP requests on localhost. [heatmap_server.py](../heatmap_server.py) is the entry point. The served application is root `index.html` and root JavaScript, with the vendored Lightweight Charts library. `client/` is a separately built React/Vite client; building it does not replace the root dashboard. FYERS supplies Indian equity/index/commodity history, masters, tick/order streams and account execution. Delta India supplies crypto data and its own signed execution/account APIs. UI broker selection does not authorize or migrate another broker's positions. Dhan-labelled selection/research helpers are not evidence of a Dhan production order runner.

The sector analysis service is read-only. EMA/RSI, Renko, KAMA, parser and straddle ownership/lifecycles are separate. Research workers use historical data and have no strategy promotion authority. Browser settings, saved preferences, armed-run configuration, broker positions and durable order intent are distinct records. A saved setting never establishes a fill or starts trading by itself. Threads cache history and stream quotes; durable state is written atomically or committed to SQLite before uncertain external order outcomes can be retried. The Python HTTP server is not a multi-user production trading service.

## Shared mathematical conventions

Let O,H,L,C denote candle open, high, low and close; previous close is Cprev. TR = max(H-L, |H-Cprev|, |L-Cprev|); first host TR uses H-L. EMA(n) is seeded with the first usable input, then EMA = previous EMA + 2/(n+1) × (input-previous EMA). Wilder RMA(n) uses the mean of n usable inputs as seed, then (previous RMA × (n-1) + input)/n. Seeding differs where explicitly stated below; identical labels do not imply identical algorithms.

Wilder RSI(n): gains=max(C-Cprev,0), losses=max(Cprev-C,0); seed their n-change means, then Wilder smoothing. RSI=100-100/(1+average gain/average loss). General analysis/Renko flat gain=loss=0 yields 50; zero loss with positive gain yields 100. The shared EMA-crossover/Delta RSI implementation returns 100 whenever loss is zero, including flat warmed history. SMA of RSI averages the last m usable RSI values; EMA of RSI seeds at first usable RSI and uses 2/(m+1).

DMI: up=H-Hprev, down=Lprev-L; +DM=up if up>down and up>0, otherwise 0; -DM mirrors it. Smooth TR and DM; +DI=100×smoothed +DM/smoothed TR and -DI analogously. DX=100×|+DI--DI|/(+DI+-DI); zero denominator gives 0 in the general/Delta implementations. ADX is Wilder-smoothed DX. Renko skips initial missing directional changes and uses its Pine recurrence's retained DI and zero-total divisor convention. [Indicators](../sector_heatmap/indicators.py), [RSI source](../strategies/ema_crossover/signals.py), [Renko source](../strategies/renko_supertrend/signals.py), [Delta ADX](../sector_heatmap/delta_adx.py).

Completed candles are chronological and deduplicated. Conflicting revisions require validation/replay, not silent mixing. Forming candles cannot confirm historical signals. Missing volume stays unavailable; actual zero is preserved. Tick/exchange time, local receipt time, candle opening time, signal evaluation time and local fill-confirmation time have different meanings. Freshness windows are module-specific; use the documented owning source rather than assuming one global tolerance.

## Sector heatmap, attribution and multi-timeframe analysis

[Analysis configuration](../sector_heatmap/analysis_config.py) defines EMA20/50/200, RSI14, ATR14, ADX14, slope lookback 5, ROC10 and minimum 210 completed candles. Timeframes are 15m, 1h, daily and weekly; weekly is derived from daily ISO-week aggregates, taking first open, maximum high, minimum low, last close/timestamp and summed volume. Benchmark closes align by exact timestamp.

For each stock, change%=100×(live price-previous close)/previous close. Contribution in index percentage points=published official weight%×stock change%/100. Official top-ten partial coverage is not scaled to 100%; unavailable ticks reduce reported coverage rather than fabricate contribution. Top contributors rank absolute contribution while retaining sign. [Official weight provenance](official-weight-attribution.md) documents the dated dataset and refresh process.

Trend structure=100×mean of five booleans: C>EMA20, C>EMA50, C>EMA200, EMA20>EMA50, EMA50>EMA200. Slope(n)=(EMA(n)now-EMA(n)five bars ago)/(5×ATR14). Slope score=clamp(50+25×tanh(3×slope20)+25×tanh(3×slope50),0,100). RSI score is RSI clamped 0–100. DMI score=clamp(50+direction×50×clamp(ADX/40,0,1),0,100), where direction=+1 only when +DI>-DI, otherwise -1. Trend=.40×structure+.20×slope score+.20×RSI+.20×DMI score. States: >=80 strong bullish, >=60 bullish, <=20 strong bearish, <=40 bearish, otherwise neutral. RSI labels use >=60/55 bullish and <=40/45 bearish; ADX >=25 strong, >=20 developing.

Relative strength ratio R=sector close/NIFTY50 close. Position=+1 if R>EMA20(R), else -1. Five-bar percentage slope=100×(Rnow/Rfive bars ago-1); ROC10=100×(Rnow/Rten bars ago-1). RS score=clamp(50+15×position+20×tanh(slope/1.5)+15×tanh(ROC10/3),0,100). Labels use >=70 strong outperformer, >=58 outperformer, <=30 strong underperformer, <=42 underperformer. Momentum=.45×RSI+.30×clamp(50+50×tanh(price ROC10/5))+.25×clamp(50+50×tanh(3×EMA20 slope)).

Breadth is the mean of available constituent percentages above EMA20/50/200, advancing and outperforming. Volume participation=.40×%relative volume>1 + .35×clamp(mean(relative volume)×50) + .25×%relative volume>=1.5; relative volume=current/20-bar average. These engines exist; live constituent historical coverage must be supplied before those components can be available. Missing components are omitted and remaining weights renormalized. Base sector weights: trend25%, RS25%, breadth20%, volume15%, momentum15%. Intraday timeframe weights 30/40/25/5%; swing 0/10/50/40%. Full alignment requires all four available timeframe states>=1 bullish or<=-1 bearish; otherwise daily/weekly agreement can produce ordinary alignment. See [analysis.py](../sector_heatmap/analysis.py) for mixed/neutral behavior.

Rotation uses distinct prior completed-history observations. Score velocity=current-prior score; rank velocity=prior rank-current rank. Leading requires score>=70 with both velocities nonnegative; lagging score<=35 with nonpositive score velocity; otherwise improving when score velocity>1 or rank improves, weakening when score velocity<-1 or rank worsens, else neutral. Acceleration compares current score velocity to the preceding one; changes above +.75 or below -.75 label accelerating/decelerating. Insufficient observations yield unavailable, never a fabricated quadrant. Cache TTLs: 15m900s, 1h3600s, daily3600s, weekly21600s; analysis checks every300s, snapshots every900s, bounded history120. Stale limits and lookbacks are listed in the source catalog. [Sector analysis design](sector-analysis-design.md).

## Planning, handoff and execution policy

[handoff.py](../sector_heatmap/handoff.py) validates planning capital, loss allowance and order/stop preferences. Optional enforce-risk-controls affects gating; a planning number is not broker margin. Per-position capital cap=60% planning capital/max positions. Available idea risk=max(0,min(idea risk,daily limit-realized loss-open worst-case risk-reserve)). Quantity is constrained by whole shares/lots, selected price-to-invalidation risk and available funds; no silent fractional lot. Inspect current parameters and selected stop/invalidation mode before interpreting sizing.

Defined-risk spreads use executable long ask/short bid, verified lot size and strike width. Debit spread max loss=net debit×lot size; max profit=(width-net debit)×lot size. Credit spread max profit=net credit×lot size; max loss=(width-net credit)×lot size. R:R=max profit/max loss. Quotes/OI/volume/spread checks are evidence gates, not fill guarantees. Handoff exports a packet to the selected recipient; it does not transmit an order. [fyers_execution.py](../sector_heatmap/fyers_execution.py) owns authenticated account-bound execution tickets and reconciliation. [automation.py](../sector_heatmap/automation.py) validates saved policies/allowed universe, segment and strategy; do not interpret a saved profile as a currently running automation.

[Equity exit plan](../sector_heatmap/equity_exit_plan.py) is planning-only (`live_execution=NOT_IMPLEMENTED`). Fixed target assigns all shares; partial-target/ST7,2 assigns floor(qty×.5) to target and remainder to a hypothetical ST runner, requiring >=2 shares. Its state transitions require entry fill then target fill then completed opposite-ST evidence; it is not the deployed Renko cash exit engine.

## EMA cloud, RSI-based FYERS strategy and legacy EMA band

Price EMA cloud uses host close EMA10/30. Shared cloud `series` labels close above/below fast EMA after at least 3×max(slow,exit period) bars; equality has no direction. Confirmed close strictly against selected exit EMA exits; wicks/equality do not. This display/legacy helper must not be confused with the current RSI runner's crossover policy.

[RSI runner](../strategies/ema_crossover/runner.py) uses Wilder RSI and its SMA/EMA, lengths 1–100. Bullish cross: previous RSI<=previous MA and current RSI>current MA; bearish inverse. Entry is a future completed signal after arming, current-master nearest-expiry ATM call/put, long premium only; exits use opposite completed RSI crossover, optional fresh underlying hard levels and optional premium step trailing. Host timeframe, lots, max trades, Paper/Live, RSI lengths/type, underlying levels and trailing settings are captured for the armed run. FYERS option submissions use MARKET type2, MARGIN, DAY, price/stop zero and `offlineOrder=False`; API/broker market-price protection applies. Tick-based profit visibility does not make RSI entries intrabar. [Module guide](../strategies/ema_crossover/README.md).

Legacy [EMA High/Low Band](../strategies/ema_band/signals.py) is separate source/backtesting logic: EMA21(high)/EMA21(low), minimum202 bars. A long breakout requires prior open<=prior high band, prior close>prior high band, current close>prior (H+L)/2; short inverse at low band. A held direction exits when current close lies inclusively inside its current band. Caller models next-bar-open fills. Do not promote this backtesting helper to the RSI or Renko runner.

Shared FYERS premium step trail defaults off. Distance d=entry premium×percentage/100 or fixed points. High-water uses fresh executable bid; level=floor((high-water-entry)/d), never decreasing. Before level1 there is no stop; at level1 stop=entry, later stop=floor-to-tick(entry+(level-1)×d). Stop never loosens. First two target allocations at levels1/2 use whole filled lots:1→0/0/1,2→1/0/1, otherwise floor30%/floor30%/remainder (at least one in each first stage). Fresh received/exchange ages allow -2..15 seconds, reject reversed/repeated samples. Partial targets and residual exits require confirmed ownership. [Step trail](../strategies/ema_crossover/trailing.py).

## Renko Supertrend calculation and entries

[Renko module guide](../strategies/renko_supertrend/README.md) and [source.pine](../strategies/renko_supertrend/source.pine) preserve the recurrence. Defaults: ATR length5, factor3, Auto brick, manual12.8, ADX off with threshold20/length14/smoothing14, widening window2, RSI slope on, retest off, all three pattern choices on. Runner defaults EMA exit on/length10, intrabar entry off, sideways off, trail off, proximity off. Engine helper defaults can differ from runner wrappers; the wrapper is authoritative for Start.

Host ATR A=RMA(TR,configured length); regime B=RMA(TR,15); low-regime L=RMA(TR,9). Ratio=A/B when available and B>0; fallback follows missing-state source rules. High regime ratio>1.2: effective factor=factor+1, Auto brick=1.5A. Low regime ratio<.8: factor-.5, Auto brick=.7L. Otherwise configured factor and A. Auto brick>=verified tick. Manual uses supplied positive brick.

Initialize synthetic close rc and open ro at first host close. For each completed host close, steps=floor(|C-previous rc|/box); if steps>=1, ro=previous rc, rc=previous rc+sign(delta)×steps×box; otherwise retained ro/rc. Synthetic H=max(ro,rc), L=min(ro,rc). Synthetic TR=max(H-L,|H-previous rc|,|L-previous rc|). Synthetic ATR is seeded immediately by synthetic TR, then previous ATR+(TR-previous ATR)/configured length, rather than SMA-seeded host ATR. Basic bands=synthetic midpoint±effective factor×synthetic ATR. Upper resets if basic upper<prior upper or previous rc>prior upper, otherwise retains prior; lower resets if basic lower>prior lower or previous rc<prior lower, otherwise retains prior. If prior ST equals prior upper, direction=-1 only if rc>current upper, otherwise +1; otherwise direction=+1 only if rc<current lower, else -1. Direction -1 is bullish/lower ST, +1 bearish/upper ST. First ST state is bearish. Host OHLC DMI supplies ADX; enabled gate requires ADX strictly >threshold.

Host EMA10/30, not synthetic-close EMAs, drive entry. Bullish ST requires EMA10>EMA30, C>EMA10, positive gap g=EMA10-EMA30, and every signed gap in the widening window positive with consecutive strict increases. Bearish mirrors using -g and C<EMA10. Window2 means one increase. Entry onset is emitted when qualifying direction differs from the saved qualification; loss of qualification rearms. Completed exit consumes its candle; flat-state rearming is separate from a same-candle reversal. Default RSI14 slope requires RSIcurrent-RSIprevious>0 bullish or <0 bearish. Flat/unwarmed/opposite slope blocks and rearms widening, so later qualification can be evaluated. A reversal marker is not itself a fill or sufficient full entry qualification.

Optional retest uses prior confirmed EMA10 as touch reference: established same-ST direction and prior/current EMA alignment; low<=prior EMA10<=high after separation. Pending touch ages at most2 bars; chronological gaps reset it. Bullish bounce requires green candle C>current EMA10; bearish inverse. Patterns: engulfing opposite nonzero prior body with current body containing it and larger; harami current nonzero body strictly inside smaller than opposite prior body; three-bar star middle body<=30% first body, final>=50%, middle on retest side of first midpoint and final close crossing midpoint. Intraday stars require no inter-candle gap. Matching gated patterns are consumed, not replayed. ADX/RSI slope still apply. Optional proximity defaults ATR basis .5: |fresh price-entry EMA10|<=distance×confirmed host ATR, or distance points; missing evidence blocks. [Retest](../strategies/renko_supertrend/retest.py), [patterns](../strategies/renko_supertrend/candle_patterns.py), [proximity](../strategies/renko_supertrend/ema_proximity.py).

Intrabar evaluation is explicitly enabled: clone the last confirmed engine, insert the broker-confirmed current candle open/updated OHLC and fresh exchange-timestamped price. Never cumulatively feed ticks into confirmed ATR/EMA state. A candidate can vanish. Full qualification, current candle identity, master/quote/ownership/capital and deduplication are rechecked before intent. Missing forming open fails closed. Forming-history recovery retries an unavailable candle at the same host opening; success updates the cached forming record, but data failure cannot authorize a substitute guessed open. The live tick and recovered forming candle can have different readiness. [Broker forming cache](../strategies/ema_crossover/broker.py), [Renko forming validation](../strategies/renko_supertrend/runner.py).

## Renko exits, holding, ownership and recovery

EMA exit on default length10, range1–1000: provisional EMA=alpha×fresh underlying price+(1-alpha)×prior confirmed EMA. Bought call/bullish exposure exits strictly price<EMA; put/bearish exits strictly price>EMA. Restored adverse exposure need not wait for a new cross. Opposite confirmed ST reversal is additional exit; EMA/hard exits do not depend on entry widening or ADX. Underlying stop uses <= bullish/>= bearish; target >= bullish/<= bearish. Missing executable option quotes can delay actual fills even when underlying exit reason exists.

Renko trail is distinct from the step trail above: full-position monotonic stop, initialized only from fresh post-fill observations; no profit activation threshold, ATR trail or partial targets. Option-premium percent default distance10 uses best executable bid and stop=best×(1-distance/100) for bought options. Underlying-points uses best high for bullish/best low for bearish and subtracts/adds distance. Cash bearish percent trails use the adverse direction; all values and timestamps must be finite, positive, ages0..15s, exchange stamp>=fill time. Stop cannot loosen; quote ordering is enforced. [Trail source](../strategies/renko_supertrend/trailing_stop.py).

Quick-loss sideways filter defaults off, max host buckets3 (editable1–10). After final exit and estimated net loss<0, buckets=floor(exit/seconds)-floor(entry/seconds)+1. Only actual first-fill-to-final-exit underlying ticks define high/low; no pre-entry or historical candle extrema. If buckets<=limit and extrema available, block new entries inside/on range. Release requires a strictly later fresh tick >high or <low, then reset eligibility; release does not enter or replay a stale signal. Adopted initial positions lack true pre-adoption exposure age and are not retrospectively classified.

Authoritative current-master session policy in runner: NSE/BSE requested cutoff15:10 IST, reduced if regular session ends earlier; MCX requested cutoff is its verified regular-session end. Cash intraday supports whole-share longs/shorts and timed exits. Cash CNC supports bought shares overnight, blocks new bearish shorts, and reconciles holdings/day-position overlap before exits. MCX options Intraday obey regular-session end; Carry forward avoids daily cutoff and protects exact expiry at previous weekday's verified session end minus30min. Holiday-aware pre-expiry scheduling is not proven by that weekday-only helper. Delta Continuous avoids an Indian daily cutoff but exact option-expiry protection applies at expiry minus60s. Saved explicit daily policies remain respected. Older15:15/23:30 prose is superseded by these source rules; always inspect runtime policy shown for a particular armed run.

Start validates configuration revision, account and process ownership, fresh data, product route and capacity; it does not replay history. Stop Renko requests cancellation/reconciliation and owned close, remaining stopping until flat. Pause an adopted manager preserves its position/claim without square-off. Adoption accepts uniquely verified filled long MARGIN options with exact lots/master/account/average/quantity; pending entries, shorts, partial lots, protective orders or other ownership block. No initial BUY is placed; adopted position counts in quota, re-entry defaults off. Restart preserves claim/pending intent but leaves adopted managers stopped until reconcile/resume. External changes pause ownership; verified full external closure can release claim without fabricated fill. [Adoption detail](renko-position-adoption.md).

Limited option-quote retry is before any order intent/dedup key, for a still-fresh confirmed signal only; uncertain submission never retries. Saved same-run Paper recovery requires identical configuration/account and flat/no pending exposure, preserving quota/run ID/P&L; fresh signals are required after recovery. History revisions replay confirmed engine from the original anchor. Source behavior is documented here; no runtime verification or session state is inferred from a saved report.

## Capital, fills, accounting and costs

Paper uses finite virtual INR capital default100000, valid0<capital<=1e9, per-run/ledger ownership. Available=initial+realized gross-fee provisions-open full premium/notional reservation. Preflight commitment uses requested exact quantity×verified multiplier×fresh ask and requires commitment×(1+fee rate+.01)<=available; reject rather than shrink quantity. Shared FYERS provision=.005 per filled side; Delta provision=.035×1.18 with verified INR conversion. Shared Paper quote spread must be <=3%. Live broker balances, actual margin checks and permission remain separate. [Paper capital source](../strategies/ema_crossover/paper_capital.py), [wallet](../sector_heatmap/paper_wallet.py), [guide](virtual-paper-capital.md).

Owned realized long premium P&L=(exit premium-entry premium)×matched filled quantity×verified multiplier. Open bought-option valuation uses executable bid, not host close/last price. Shorts use inverse sign and executable ask where supported. Partial fills establish only actual quantity; requested/accepted does not equal filled. Exact fill timestamps can be unavailable; local confirmation/spot observations are labelled accordingly. Older missing evidence remains unknown. Journal snapshots freeze settings/indicators/order reconciliation at the event. Portable XLSX stores recorded trades/orders plus lossless chunked JSON; this supersedes old workbook layout claims. [Portable export](../sector_heatmap/portable_journal.py).

Implemented Sensex-options cost MODEL (dated estimate, not a current fee promise): brokerage15 per executed order, exchange .000325×turnover, SEBI .000001, sell STT .0015, buy stamp .00003, GST .18×(brokerage+exchange+SEBI). STT/stamp cumulative runner/day half-up whole-rupee amounts are allocated per order; exchange/SEBI/GST half-up paise. Applies to supported BSE Sensex CE/PE fills dated>=2026-04-01. Realized net=gross-proportional entry costs-exit costs-additional slippage points×sold quantity×multiplier×2. Open liquidation additionally deducts remaining entry charges and estimated exit fee at fresh bid; other routes can show costs unavailable. Actual fill slippage is already embedded, never double deducted. [Costs](../strategies/renko_supertrend/costs.py).

Delta Renko regular-option cost estimate uses recorded native commission, else min(qty×units×observed index×saved taker rate,qty×units×premium×.035), plus estimated18% GST. Entry allocation is proportional to sold quantity; missing fee/index evidence leaves unknown. Open liquidation fees remain unavailable without required index evidence. No expiry/exercise/liquidation costs included. INR policy requires official-source identity, positive rate, native USD/equivalent INR and verification age<=86400s with at most2s future skew in the UI. INR display is not broker settlement, FX trading or permission to value unsupported quanto/inverse contracts. [Delta costs](../strategies/renko_supertrend/delta_costs.py), [currency policy](../sector_heatmap/delta_currency.py), [UI conversion](../delta-inr.js).

## Delta manual and RSI strategy

This is OHLC-derived evidence, not recovered tick touch. Cross has priority. Exits use opposite completed cross rather than a touch entry. Optional ADX14 entry threshold25 strictly exceeded; momentum requires completed close>previous high with RSI-MA slope>0 bullish, inverse bearish. These entry filters do not suppress protective exits.

No futures fallback. Legacy saved futures runner Both/Long-only remains its recorded route until explicitly replaced; manual exact-symbol options are not automatic mapping. Manual limit supports IOC/GTC and tick-aligned positive price; market supports IOC without limit. Telegram stop-limit is a separate exact-contract path. Runner orders use fresh executable IOC limits; shorts/reductions use correct opposite side/reduce-only and confirmed exact owned quantity. Durable client request/account/product/terms are reconciled; UNKNOWN is never blind resend. Wallet positive balance is not locally guessed margin.

Legacy Delta percentage/points trail mirrors shared step allocation and stop rules using asks for shorts; no initial stop. Delta ATR mode is separate implemented functionality: ATR14 Wilder from completed traded-contract candles, distance=ATR×configured multiplier. Initial stop is entry-distance long/entry+distance short, rounded adversely to tick; reject invalid distance/quotes. Best-price ratchet updates with fresh nonolder ATR candle, never loosens, preserves established stop even when new ATR unavailable; full-position exit, no staged targets in ATR mode. [Delta trail](../sector_heatmap/delta_trailing.py). These modes do not implement the trailing research shortlist.

Stop Delta polling leaves position; explicit Close is separate. Saved held-position monitoring intent can restore exit-only monitoring after account/ownership reconciliation; intentional stops remain stopped. Limit/IOC residuals can remain; no guaranteed exchange stop. History archives append verified candles and allow selected older read-only ranges. Dedicated Delta monitoring, lifecycle/journal reconstruction, currency and adaptive research modules have separate state and failure messages. ## KAMA strategy

[KAMA source](../sector_heatmap/kama_strategy.py): defaults length10, fast2, slow30, minimum efficiency.35, prior breakout5, cooldown2, reclaims on, slope lookback8, minimum slope.10 ATR/bar, entry09:15–15:10 and square-off15:15–15:30 IST. ER=|Cnow-Cn bars ago|/sum of absolute n consecutive close changes; zero noise→0. SC=(ER×(2/(fast+1)-2/(slow+1))+2/(slow+1))². KAMA unavailable before length bars, then seed close and update previous KAMA+SC×(close-previous KAMA); returned line rounds4 decimals.

Slope=(KAMAnow-KAMAlookback ago)/lookback, normalized |slope|/mean of last lookback TR (not Wilder ATR14). Long requires ER>=minimum, rising KAMA, close above prior breakout high or allowed reclaim low<=KAMA<close, normalized slope>=minimum and signed slope>0. Short mirrors it. Same-direction re-entry requires bar index-last exit>cooldown. Held long exit close<KAMA and falling, short inverse; square-off takes priority. Incomplete bars and unconfirmed broker ownership block exit state machine; positive quantity/max-risk/stop and absent external account position gate entries. Web routing/funds/product guards remain separate from this signal engine. Older KAMA Pine versions are preserved research/reference variants, not identical active semantics.

## Chart overlays, five-minute zones and feed confidence

[Renko UI host zones](../renko-supertrend.js) use separate completed broker5m candles even when the execution chart timeframe differs. Pivot p must have high strictly greater than all two prior/two following highs (supply), or low strictly smaller (demand). ATR14 here is arithmetic mean of14 TR ending at pivot, not Wilder ATR. Supply band=[max(Op,Cp),Hp]; demand=[Lp,min(Op,Cp)]. Within the two following completed candles, lowest close must be<pivot low and supply-near minus lowest close>=ATR, or highest close>pivot high and highest close-demand-near>=ATR. Confirmation is close time of second following candle. Latest qualifying supply/demand is retained; broken supply when later close>upper, demand when close<lower, equality/wick alone does not break. Shade begins at pivot origin retrospectively; the interval before confirmation was not a tradable known zone. Broken state is retained until replaced. Bands are host prices on either host/synthetic chart, display-only, no entry/exit gate.

LED is green only if current chart snapshot elapsed0..5s, market connected/fresh, finite tick exchange age0..15s and order stream connected. Closed market or stale/missing tick changes confidence; a socket connected flag alone is insufficient. Tick age uses server time and elapsed UI age. A fresh tick does not prove current candle open/history ready, nor broker execution health. Error/assessment can show forming unavailable while tick connection remains fresh. History recovery retries do not override entry fail-closed checks. [Chart health and zones](../renko-supertrend.js), [assessment](../renko-assessment.js).

Other root cloud overlays are separate algorithms: configurable ATR base/departure supply-demand zones, EMA10/30 fill, RSI bands0–40/40–60/60–80/80–100, Bollinger SMA with population standard deviation, session markers and fixed/floating Red Bar Fibonacci, CPR and previous period levels. CPR pivot=(previous H+L+C)/3, midpoint=(H+L)/2, reflected=2pivot-midpoint; TC=max(midpoint,reflected), BC=min. Fixed session Fib and latest completed red floating Fib levels use price=high-(high-low)×ratio, ratios .382/.5/.618, and configured session references in [redbar-overlays.js](../redbar-overlays.js); sessions/timezones persist separately.
