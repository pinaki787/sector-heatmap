# Sector Pulse deployment guide

Updated 8 October 2026. [Technical rules](technical-guide.md), [user operations](user-functional-guide.md), [source/default catalog](source-reference.md). Installing files does not authorize orders, start a strategy, or establish that a broker connection is usable. This guide describes the current release procedure; runtime state must be checked at the time of any update.

## Package and platform boundaries

The versioned source archive is generated from a reviewed Git commit, excluding credentials, private runtime files, journals, caches and generated market/research data. Its filename contains date and short commit. SHA256 identifies the exact archive. The public GitHub repository must never contain the private credential overlay. The private overlay is unencrypted and separate, locally owner-readable only; its checksum/member manifest and restore notes are also private. Matching source and credential archives are separate deliverables; changing source commit does not require re-exporting or uploading credentials.

Python3.10+ with venv/pip and Node20.19+ with npx are prerequisites. The launcher uses pnpm10.17.1 with frozen client lock. Python runtime versions are pinned in requirements.lock: FYERS SDK and its HTTP/WebSocket/AWS dependencies, certifi, setuptools, openpyxl/et-xmlfile, timezone data, NumPy/pandas/pytz for straddles. The optional offline research requirements separately add VectorBT, OpenAlgo, tqdm, Plotly, matplotlib and python-dotenv; their bounds are not a reproducible exact research lock. Consult [requirements.lock](../requirements.lock), [research dependencies](../requirements-research.txt), [client manifest](../client/package.json).

macOS/Linux use POSIX launchers; Windows uses native cmd.exe .bat files. Windows timezone data and OS byte-range locks replace Unix fcntl; Windows execution has not been tested in this audit. Native WhatsApp polling is macOS-only: Swift compiler, installed WhatsApp, Accessibility and Screen Recording permissions. Manual parsers and Telegram do not require the native reader. Journal XLSX exports use Python/openpyxl rather than an installed Codex cache. No Codex runtime, spreadsheet plugin or developer home folder is required for journal export. Some offline historical research scripts still require separately acquired data and their own input preparation.

NIFTY/SENSEX straddle source is bundled under strategies/long_straddle with NumPy/pandas runtime dependencies. Explicit script environment overrides win; this existing development host retains legacy installed scripts when present; fresh hosts use bundled fallback. Deliberately select bundled scripts on an existing host only after stopped/exposure-safe verification; replacing files does not reconcile old process state. The bundled straddle scripts use naive local wall-clock datetimes; configure the destination system timezone to Asia/Kolkata for their schedules. Other core services use explicit IST. Source-only release contains all dashboard module code, but native WhatsApp remains platform-limited, broker auth is environment-dependent and research datasets are not distributed.

## Fresh installation

1. Verify archive SHA256 against the delivered manifest, inspect the source commit, and extract into a private local folder with sufficient disk space. Do not extract a private overlay into a shared/public/synced source repository.
2. Run setup-only first: on POSIX `HEATMAP_SETUP_ONLY=1 sh setup_and_run.sh`; Windows `set HEATMAP_SETUP_ONLY=1` followed by `setup_and_run.bat`. This creates .venv, installs the runtime lock, builds client, compiles the macOS WhatsApp helper when Swift exists, and runs scripts/check_setup.py. It does not start the dashboard or a runner.
3. For research dependencies explicitly set HEATMAP_INSTALL_RESEARCH=1 during setup, or install requirements-research.txt with the project interpreter. Missing optional research packages do not block ordinary runtime readiness; required NumPy/pandas for bundled straddles do.
4. Read the private restore notes if importing your approved credential overlay. Otherwise copy .fyers.env.example to .fyers.env and configure your own broker keys privately. Copy .env.example to .env only for runtime switches. Never paste secrets into docs, source, logs or chat.
5. Start the localhost dashboard with `sh run_live_heatmap.sh` or `run_live_heatmap.bat` after installation. Setup-and-run without setup-only starts the server after installing/building; this still does not authorize a strategy Start. Default port8080 can be selected with HEATMAP_PORT. The root dashboard is served separately from the Vite client build.
6. Verify broker/data/account identity, contract master and intended environment, then review Paper/Live and every instance's settings before any deliberate Start. Setup success is not live fill verification.

First setup can require network access for package downloads and broker/public metadata. A venv copied across OS/architecture is not portable; recreate it from the lock. Windows needs Python launcher or python on PATH; POSIX python3/python. On macOS the Swift helper build produces .private/whatsapp-reader with mode0700 and does not start polling. If Swift is absent, the setup prints the limitation and manual/Telegram workflows remain available.

## Credentials and authentication portability

FYERS discovery: environment, explicit FYERS_CONFIG_FILE and platform configuration candidates, project .fyers.env, with cached-token precedence handled by config.py. Token cache is normally ~/.fyers/token.json, overridable with FYERS_TOKEN_FILE. The private overlay relocates the cached session to .private/fyers-token.json: set FYERS_TOKEN_FILE to its absolute destination path if using that copy. Effective .fyers.env contains approved configured keys/session fields. FYERS redirect URI/port must match the registered application. Expiring access/refresh sessions and browser2FA may need renewed login; do not assume a copied token still works.

Delta application uses .private/delta-india-credentials.json, configured environment overrides and the shared India config source. Keys need account/trading permissions and allowed destination public egress IP; India endpoint is distinct from global Delta. .private/delta-india-mcp.env is an integration file for the separate MCP client, not automatic dashboard authentication. The overlay retains shared config as .private/delta-shared-config.env; restore to ~/.delta-exchange-mcp/config.env only if that separate client is needed, preserving unrelated host configuration. Masked credential fields clear after saving; credential files are denied by static serving.

OpenAI key comes from environment or ignored .env.local. Keys/configuration alone do not establish current service availability or spending limits. Telegram uses private bot/channel configuration when present; this deployment's approved credential export found no Telegram configuration file, so it does not fabricate a token. Bot membership/permissions and webhook state must be verified on destination. Polling/Auto never resumes merely from restored credentials. WhatsApp native executable/OS permission grants are destination-specific and must be rebuilt/reapproved.

Private archive and members use0600; directory entries0700. Restrict Windows ACL to the user account because POSIX modes do not provide equivalent Windows access control. The overlay omits positions, journals, order intent, ownership locks, queues, caches and polling databases. This is a new installation configuration transfer, not safe migration of an active trading process. Original copied .env or Delta capability flags may be enabled: inspect them before launch. Tokens and secret files remain only local and are never included in git archive.

## Live authorization and module-specific gates

All four standard launchers explicitly read/validate FYERS, KAMA and trade-parser live switches as0/1 from environment/.env; fresh source defaults0. SECTOR_PULSE_ENABLE_FYERS_LIVE_ORDERS gates its supported execution paths; KAMA also requires its own gate; parser uses SECTOR_PULSE_ENABLE_TRADE_PARSER_LIVE_ORDERS, optional protection additionally SECTOR_PULSE_ENABLE_PARSER_PROTECTION. Delta uses its separate DELTA_INDIA_ENABLE_LIVE_ORDERS and authenticated account capability. Enabling a capability does not start a runner or establish funds/margin.

Straddle process bridges have separate explicit LIVE start confirmation and external/bundled script CLI--live; they are not universally guarded by EMA/KAMA/parser environment switches. Their direct CLI now defaults Paper, but an explicitly confirmed LIVE request can launch its broker code. Paired orders are not atomic. The standalone NIFTY credit-monitor CLI also has its own explicit --live capability. Do not rely on one global gate to sandbox every script in the repository. Setup validation never calls a straddle Start, order route or account mutation.

## Safe update and restart procedure

1. Record the currently served checkout/PID/port, source commit, active broker/account, each instance's mode/running/exposure/pending intent and ownership. Read current broker positions/orders/holdings where authorized. Historical reports do not prove today's flatness.
2. Back up private state and journals into a separate private location, including SQLite with a consistent backup mechanism rather than blindly copying a live transaction. Keep credentials separate. Do not include backups in Git or public deliverables.
3. Prepare/update source and run setup-only in a separate isolated folder while the existing runtime remains untouched. Review diffs/defaults/contracts and dependency changes. Do not overwrite an armed run's settings or perform a restart merely because tests pass.
4. Schedule interruption only with explicit operational authority and an exposure/ownership plan. Renko Stop seeks reconciled flat; adopted Pause preserves exposure; Delta Stop can leave position; straddle Stop/process termination does not prove broker closure. Use actual broker reconciliation, not a UI button label.
5. After stopping safely, apply the reviewed source/dependencies and restart only the intended service. Adopted managers remain stopped until reconcile/resume; Delta held monitoring intent may restore exit-only monitoring; verify the exact module behavior. Do not automatically rearm entries after restart.
6. Check static asset revision, service source revision, fresh broker/account/master/quotes, candle-open readiness at a minute boundary, saved ownership and reconciliation. Resolve UNKNOWN before any new entry. Confirm intended Paper/Live mode and capital settings. Preserve prior quota/run identity where supported by guarded recovery.

Never migrate active state and start two monitors against the same account/contract. OS locks protect only processes sharing their lock storage; two machines with separate directories do not share a broker-global lock. Broker reconciliation and explicit migration control remain necessary. Atomic local files are not a broker transaction.

## Verification and release procedure

Use project interpreter with unittest discovery for tests/ and strategy suites; `node --test tests/*.test.cjs` covers root dashboard JavaScript. `python scripts/check_setup.py` reports import/timezone/platform readiness without constructing a runner. `python scripts/generate_source_reference.py` refreshes exact source/default catalog; `python scripts/check_documentation.py` validates canonical local links and module coverage. `python scripts/render_user_functional_guide.py` regenerates the browser guide. Review secrets using staged content and explicit path allowlists; never blanket stage output/, tmp/, .private/ or broker configuration.

Build source archive from exact committed HEAD, then verify archive paths and SHA256. Verify pushed remote main matches commit before claiming synchronization. A release report should record test counts/failures, OS actually exercised, setup-only build, isolated credential-free startup, source commit, limitations and whether a runtime restart actually occurred. Source publication and package verification are not a deployment to the running backend.

Isolated startup checks must use a new HOME/token path, no inherited broker credentials, live capabilities off and a nonconflicting localhost port. Start only the new temporary service, fetch a read-only page, then terminate that temporary process. This protects existing runtime and avoids credentials being used during release verification. Current audit does not claim cross-OS broker execution or live-fill verification.

## Troubleshooting

- Dependency/build failure: inspect setup diagnostics, verify Python/Node versions, network and lockfile; do not loosen frozen locks silently or start the dashboard after failed setup. Recreate venv on architecture changes.
- FYERS TLS/auth errors: validate certifi trust, system clock, app/redirect/port and token expiry; use supported browser renewal. Never disable TLS verification to make connection appear healthy.
- Delta auth errors: verify India key environment, permissions, IP whitelist, clock/signature and wallet read; no local guessed margin or currency conversion can resolve broker rejection.
- Missing master/contract: entry blocked; refresh authoritative master, listed expiry, tick, units and underlying route. No unsupported futures fallback or fabricated lot.
- Green LED but forming unavailable: tick connection and broker candle open are distinct. Keep intrabar entries blocked until verified current candle; allow history recovery retries, inspect stale/error state. Green is snapshot health, not fill proof.
- Stale quote/UNKNOWN order/quantity mismatch: reconcile existing exact intent/account/contract; never resend blindly. Preserve position and ownership evidence for manual review.
- Straddle module missing: select bundled reviewed path or explicit installed override; ensure NumPy/pandas, runtime directory and broker credentials. Existing external sources can drift; validate their formula/CLI shape before isolated Paper patching.
- WhatsApp unavailable: macOS only, helper built, selected chat, unread metadata and OS permissions verified. Access errors fail closed; no claim of complete ingestion. Telegram needs actual bot/channel access, not a signed-in personal Telegram account.
- Export unavailable: verify openpyxl import/project interpreter and recorded evidence; no Codex cache should be required. Missing old P&L/fee fields remain unknown, not zero.
- Research source cannot run: supply missing historical inputs separately and install optional dependencies; no archive contains the bulk/private datasets. Research output cannot be promoted automatically.

## October 8 source deployable

Run `python3 scripts/package_release.py` on the reviewed committed checkout. Optional `--ref COMMIT` pins a prior commit; `--output DIRECTORY` chooses a destination. The default ignored `output/releases/` holds the date/commit-named tar.gz, SHA256 file and per-file manifest. Uncommitted edits are excluded. The builder rejects private/generated directories, runtime databases/logs, credential filenames and common credential patterns; still review staged source before publication.

Verify with `shasum -a 256 ARCHIVE.tar.gz` on macOS or `sha256sum ARCHIVE.tar.gz` on Linux, comparing with its `.sha256` file. Extract into a fresh directory and use setup-only as above. The release includes the October 8 Renko/ATM-option changes and updated browser user guide. No credential overlay is regenerated, no active state is migrated, and archive creation does not restart services or runners. Read the [release notes](release-notes-2026-10-08.md) before upgrading.
