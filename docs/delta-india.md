# Delta Exchange India workspace

Select **Delta India** in Sector Pulse. The requested strategy execution is now **Buy ATM call / buy ATM put**: the perpetual chart supplies underlying RSI signals; actual positions are long options. The new UI requires the matching backend capability before allowing a new Submit or Start. Existing legacy runner configurations remain unchanged until explicitly stopped/replaced. It uses the India production API at `https://api.india.delta.exchange`; it has its own paper ledger and live order ownership records. Dhan and FYERS selection and runners are independent.

**Connection:** use your existing India key and secret in the dashboard's masked Connection settings, then click Connect India account. The server checks the credentials through a signed wallet read. The key needs the required account and Trading permissions, and the machine's public egress IP must be in its Delta whitelist. The API secret is shown only at key creation; the management page cannot recover it. Do not send it in chat. Environment variables `DELTA_INDIA_API_KEY` and `DELTA_INDIA_API_SECRET` override local settings. `DELTA_INDIA_ENABLE_LIVE_ORDERS=0` disables live capability. An enabled gate alone does not establish account connectivity.

Credentials are saved in `.private/delta-india-credentials.json`, owner-readable/writable only. After successful authentication, `.private/delta-india-mcp.env` provides the same credentials to the official MCP; neither file is served by the HTTP handler or committed. Browser fields are cleared immediately on Connect; keys never enter browser storage or response payloads. The official MCP supports `DELTA_MCP_CONFIG_FILE` for this shared file. Reload/restart its connection after configuring it if the client has not refreshed the tool list. The MCP installation and the dashboard adapter are separate clients of the same India API.

**Manual order:** choose LIVE, an exact listed contract, Buy/Sell, whole contract quantity, a positive tick-aligned limit price, IOC or GTC, and optional reduce-only. Click Submit Order directly. There is no Review/Confirm step. Limits bound the submitted price; IOC cancels any unfilled portion. Market and stop orders are not offered by this adapter. Instrument ID, contract units, operational state, fresh bid/ask, wallet availability and real-time product position are checked internally. The broker makes the final permission/margin decision; no local currency conversion or invented required margin is used.

Orders have a durable intent before submission, unique client order IDs and an account identity binding. Repeated requests cannot submit again. An uncertain network response stays UNKNOWN until broker lookup reconciles it; even a missing lookup never triggers blind retransmission. Order responses must match exact product, side, quantity, limit and reduce-only terms. Filled contracts and average fill come from verified cumulative broker evidence. Read fills provides the exact owned order's fills. Cancellation targets an explicitly owned order only, and an uncertain cancel is reconciled before another attempt.

**Runner:** select PAPER or LIVE, contract quantity, timeframe, Wilder RSI length, RSI MA length and SMA/EMA, then click Start Runner directly. It arms at the last completed candle and waits for a future crossover; there is no historical signal replay. Bullish crossover buys the selected contract. In futures Both mode a bearish crossover sells short while flat; Long only does not open shorts. An opposite completed crossover closes the owned quantity first and does not reenter on that candle. Options permit Long only on the explicitly selected contract; there is no automatic ATM/Call/Put strike mapping. Runner orders are fresh bid/ask, tick-aligned IOC limits. Partial fills establish only the actually filled quantity. Pending/uncertain orders block subsequent orders. Broker positions that differ from owned quantities block execution. Candles over 30 seconds late are skipped after a reconnect. Optional application-managed trailing is off by default and applies only to runner-owned positions. Choose a percentage of the original actual filled entry (10% default) or quoted price points. Whole filled contracts are split into first target, second target and residual runner: 1 → 0/0/1, 2 → 1/0/1, 3 → 1/1/1, 4 → 1/1/2, 10 → 3/3/4. At one favorable step the first allocation exits and the stop moves to entry; at two steps the second allocation exits and the stop moves one step into profit. Later the residual stop ratchets one step behind, never loosening. Shorts mirror this using fresh asks; longs use fresh bids. Partial fills reduce only actual filled quantities; pending orders and durable exit intent guard against duplicates. An opposite completed crossover closes the residual before trailing targets. There is no initial stop. Monitoring requires the runner and connected backend to remain running; Stop, backend restart or disconnection suspends protection. These are reduce-only IOC limit exits, not resting exchange stops, and unfilled residual contracts can remain. Manual orders do not receive this trailing protection.

Stop Runner stops polling and leaves an owned position in place. Close runner position is a separate direct explicit action. After a server restart, a held position with saved active monitoring intent reconciles ownership and resumes exit-only monitoring using its recorded settings. Intentional stops remain stopped; legacy positions without saved intent require explicit restoration. A partially filled IOC exit can leave a residual position; the status reports it and the explicit Close action can close the verified remaining quantity. No claim is made that limit exits will always fill.

**Paper:** Submit records a local simulation using fresh ask/bid, without any broker order. Contract notional is labelled as notional, not margin or cash invested. P&L uses verified linear contract units in the quoting asset and excludes fees/funding. Quanto/inverse contracts are unavailable until their valuation and sizing are explicitly supported. Only supported operational listed derivatives are selectable; quote denomination USD does not imply a forex instrument or a USD/INR conversion.

Primary references: [India API documentation](https://docs.delta.exchange/), [official Delta MCP](https://github.com/delta-exchange/delta-exchange-mcp), [India API key management](https://www.delta.exchange/app/account/manageapikeys), [Codex MCP configuration](https://developers.openai.com/codex/mcp).

Manual tickets support `limit_order` (default) and `market_order`. Market tickets omit `limit_price` and use IOC, cancelling unfilled quantity; fills can span prices. Limit price and IOC/GTC selections remain available for limit tickets. Paper tickets continue to simulate fresh executable bid/ask, without resting limit simulation. RSI runner entries/exits continue to use fresh bid/ask IOC limits. API reference: https://docs.delta.exchange/ ; India IOC market policy: https://guides.delta.exchange/delta-exchange-india-user-guide/exchange-sop-and-policies/allowed-trading-bands

Chart Buy Call buys the nearest-expiry ATM call; chart Buy Put buys the nearest-expiry ATM put, never a short put. Routing uses the chart contract underlying, a fresh listed perpetual ticker spot price and a fresh complete India option catalog. Expired contracts are excluded, expiry takes priority over strike distance, and equal strike distances choose the lower strike deterministically. Both buttons reuse ticket workflow, whole contract quantity and market/limit settings, but always open long options. The resolved exact contract and expiry are displayed; the server resolves again on submission and blocks if the choice changed or evidence is unavailable. No futures fallback occurs. Limit price is option premium, not the underlying chart price. Existing runner direction and RSI crossover behavior are unchanged.

The selected chart uses the public India WebSocket at `wss://public-socket.india.delta.exchange`: `ob_l1` supplies executable best bid/ask and `candlestick_<resolution>` supplies traded-price forming OHLC/volume. Updates render at most once per second. Initial REST history, reconnect/gap recovery and candle-boundary reconciliation are labelled separately; the runner continues its existing independent REST polling and fresh mutation preflight. Socket heartbeat loss reconnects with exponential backoff up to 30 seconds, resubscribes and repairs history. Symbol/timeframe or RSI/RSI-MA settings stop the old subscription and reload matching history; SMA/EMA smooth Wilder RSI and completed-candle display analysis excludes forming bars. Revisions replace the matching candle timestamp; out-of-order packets and old sockets cannot alter current display. Disconnected/stale status is visible. API credentials stay in owner-only private files, never in the public socket or browser storage; fields stay empty, show saved masked indicators and blank updates preserve saved values. Chart actions are labelled Buy Call and Buy Put; both are long option purchases.

Buy Call / Buy Put are bounded strategy-gated clicks, not waiting runners. The server checks the underlying latest completed Wilder RSI cross against the selected RSI SMA/EMA and lengths: bullish for a call, bearish for a put, within 30 seconds of candle close. It requires the displayed completed-close identity, re-resolves fresh exact nearest-expiry ATM contracts and rejects a changed contract, stale/absent signal or previously used underlying/candle/direction. Submitted intent and paper entries persist the consumed signal, including uncertain/rejected live outcomes. No qualifying signal means no financial POST. Ticket Submit and existing runners retain their own behavior. No new automated exits or waiting lifecycle is added to chart buttons.

Live account visibility includes all broker-reported open margined positions, including external/manual trades, with entry/mark, signed contracts and native settlement currency. Broker unrealized P&L takes priority. Only verified linear vanilla contracts can use calculated signed-contract mark-to-market, labelled before fees/funding; otherwise unavailable remains explicit. Recent broker fills cover a labelled 30-day window with authenticated cursor pagination, up to 2000 fills, deduplication and explicit incomplete/error state. Fill commission and fill-level realized P&L are shown only where supplied; the metadata new-position realized P&L is separately labelled cumulative and is never summed into an invented all-in result. Account reads refresh every 20 seconds while the Delta view is open, with timestamp, errors and manual Refresh account. Paper history remains separate. The sidebar Trading Strategies group preserves EMA Band, RSI based SMA, Delta India, KAMA Strategy and Trade Parser view IDs and order.

### Broker position lifecycle history

Authenticated 30-day fill history is displayed primarily as one row per position lifecycle, using deterministic chronological weighted-average accounting scoped to the configured account, product, and settlement currency. Broker post-fill signed position sizes establish opening boundaries and reconcile scaling, partial exits, and reversals. Order IDs identify the component executions; they are not treated as position IDs. A reversal fill is allocated between closing and opening lifecycles, with its commission apportioned by contracts. Latest broker cumulative realized position P&L is shown separately and never summed across fills.

Entry/exit values and calculated gross realized P&L require verified linear contract units and equal quote/settlement currency. Closed reconciled lifecycle net deducts reported commissions only; it excludes funding and other adjustments and is not all-in account profit. Partial open positions show matched gross realized P&L and total known lifecycle commissions separately; net is unavailable until closure. Missing opening evidence, quantity discontinuities, absent units/fees, and truncated history are explicit. Raw projected fills and allocations remain expandable; no pairing invents opening prices or converts currencies. Account/history reads do not place orders or start a runner.

Delta's Indicators menu includes synchronized SMA/EMA-of-Wilder-RSI and MA-length controls beside the RSI toggle. Price EMA10/30, cloud, Bollinger, volume, RSI, session markers, supply/demand and Fibonacci toggles are independent and may coexist. Session/zone/Fibonacci overlays use actual selected-contract candles and remain off by default. Multi-timeframe RSI, daily reference levels and automatic supplied support/resistance remain unavailable for Delta, with reasons in the menu; manual Draw remains supported. Selecting smoothing updates display and the existing bounded click gate settings without starting a runner. Lifecycle row color prefers closed net after commissions, otherwise explicitly labeled matched gross; zero, missing and incomplete P&L remain neutral, with signed values retained.

### Strategy-managed Submit

Submit Order entries require the selected contract's latest completed bullish (buy/long) or bearish (sell/short) RSI crossover, using the chosen timeframe, Wilder RSI length, SMA/EMA and MA length. The crossover must still be within 30 seconds of candle close and match the displayed completed timestamp. Settings are mandatory on public paper/live entry endpoints. Conditions are revalidated before recording/submitting; consumed signals cannot create another entry even after changing smoothing settings. Chart Buy Call/Buy Put retain their separate underlying-signal ATM routing.

A qualifying Submit entry snapshots its settings and monitors only its resulting position for the opposite completed crossover. It never waits to enter, reverses, reenters, or applies trailing. Live entries require the exact broker product to be flat; existing paper/owned lifecycles must first be closed/reconciled. Pending GTC entry quantity is cancelled before exiting confirmed fills on a qualifying opposite cross. Reduce-only IOC exits reconcile actual fills, latch residual exit intent, and never blindly resend unknown orders. Explicit reduce-only actions retain position/quantity validation while bypassing entry signals. Paper reductions use the opposite side of the same owned contract; selected quantity may partially reduce it.

Existing Start Runner behavior is retained. Stop strategy monitoring leaves the owned position intact; Close owned strategy position explicitly closes/reduces it with verified ownership. Backend restart restores only a held position with saved active monitoring intent, after reconciliation, in exit-only mode. Intentional stops remain stopped. History/authentication/ownership failures stop monitoring and report the failure. This is backend-managed protection, requiring a running, connected process; it is not a native exchange stop.

A prominent workflow P&L panel distinguishes Paper from Live. Paper unrealized P&L uses held-contract executable bid for longs/ask for shorts, verified contract units and remaining contracts; wrong-contract, missing or stale (>15s) quotes show unavailable. A separate public held-contract subscription is used when the chart differs. Realized paper exits stay grouped by quote currency, before fees/funding. Live selected-contract P&L retains authenticated broker fields, settlement units and snapshot timestamps. Flat armed Paper shows Awaiting entry without invented P&L. Frontend Submit remains blocked when the served backend lacks the strategy-managed capability flag, avoiding a misleading partial rollout.

Paper display settings (contract, timeframe, RSI/MA, quantity, order type and trailing inputs) persist locally without credentials or automatic runner activation. LIVE workflow is never restored automatically: a saved LIVE selection reloads as Read-only. First migration restores the user's existing Paper runner configuration as display settings only. Read-only, active strategy, ownership/pending reconciliation, invalid quantity and unavailable live capability have explicit control-state explanations. Stop updates button availability immediately from returned status.


### Candle-extreme EMA touch entries and chart execution markers

The Delta-specific entry calculation retains completed RSI crossovers and additionally supports EMA touch returns. For a long bounce, both prior and current closing RSI must be strictly above their respective RSI EMA, while RSI hypothetically calculated at the completed candle low reaches or crosses its corresponding EMA. Shorts mirror this using the candle high and closing RSI below EMA. Extreme RSI uses the prior completed Wilder gain/loss state, and extreme EMA uses the prior completed RSI EMA. No tolerance or recorded intrabar RSI path is inferred. Evidence is labeled `CANDLE_EXTREME_DERIVED`; SMA retains crossover entries only. Crossovers take priority and `cross_direction` remains unchanged for exits. Backend deployment requires a process reload; it does not auto-resume a runner.

Overlay captions occupy a separate rail below price candles. Latest shows only the current active session on the current IST date; historical view restores historical O/R references with lines ending at the next session. Opening and first later red candle formulas remain unchanged. Indicator toggles, Bollinger settings and session opening settings persist independently. Earlier/Later and Latest navigate the loaded history; refresh anchors a historical viewport by timestamp. The stream retains previously loaded bars across recovery rather than discarding them when new bars arrive. The initial provider history request remains 500 bars; navigation does not claim unlimited provider history.

Paper markers derive from durable actual ledger entry and partial exit fills. Live markers require actual broker fill rows matching strategy-owned order, product, symbol and side; order creation times and unfilled/rejected intents are never execution markers. Entry and exit markers share lifecycle association and display contracts, exact price and fill timestamp in IST. Marker triangles use the actual fill price and the fill time within its candle. Switching workflow or instrument filters the markers without changing account or runner state.


Account, live positions, lifecycle history, Paper history and selected-workflow current positions use native keyboard-accessible disclosures with independent persistent expansion choices. Collapsed summaries retain workflow labels, open-position counts, known unrealized P&L and snapshot freshness. The selected-workflow table shows actual remaining filled contracts, entry, executable Paper bid/ask valuation or broker Live mark/P&L, currency and valuation time; watching while flat is not a position. Paper history includes entry/exit dates and seconds in IST, remaining quantity, actual fills and durable reasons. Legacy missing signal reasons remain unavailable; legacy EXPLICIT_CLOSE exit labels are explicitly marked as unverified rather than rewritten.


### Underlying-signal ATM option strategy

`strategy_mode=ATM_OPTIONS` explicitly separates the underlying perpetual signal symbol from the actual option execution symbol. Bullish completed RSI crossover or approved EMA candle-extreme touch buys a call; bearish buys a put when flat and Both directions is selected. Both entries buy premium only. Fresh catalog/underlying spot selects the nearest still-unexpired expiry and closest strike (lower strike breaks ties); option contract identity, units, tick and executable bid/ask are verified again. There is no futures fallback or option writing. Missing/stale/expired route or a signal older than 30 seconds fails closed. Explicit Start arms future completed signals only; Submit is one-shot and never waits for an entry.

Held puts exit on a bullish underlying crossover; held calls exit on a bearish one. Exits reduce the actual filled option remainder, using that exact option's quote/product. No same-bar reversal occurs. Optional trailing follows the bought option's premium bid for both calls and puts, preserving partial fills and duplicate guards. Entry signal/reason, underlying identity and option identity persist with ownership records; new Paper exit records retain verified exit reason, signal direction and signal-close timestamp. Restart preserves positions and restores recorded active monitoring in exit-only mode after reconciliation; it never starts new entries.

The primary chart retains underlying candles for signals. A separate Actual option execution chart loads the held or most recent owned option's premium candles and exact-price confirmed fill markers, with Paper/Live filtering. Option premium RSI is not displayed as an underlying signal. No option chart is fabricated when there are no recorded option executions.

The Strategy execution selector defaults to ATM options on each page load. Futures is an explicit alternative for listed perpetual futures: bullish RSI entries buy long, bearish entries sell short, and the opposite crossover closes the held position. The futures selector requires the matching backend capability; changing the selector never starts a runner or submits an order.

Recovery: temporary public-data network errors, HTTP 429 and HTTP 5xx suspend execution and retry with a bounded delay. On reconnection, held positions scan contiguous completed candles since the last consumed candle for the first opposite crossover; historical entries are never replayed. Exit intent is persisted on the owned position before requesting a close and survives quote failures/partial fills. Pending Live orders reconcile before further exits. Missing history blocks entries. Ownership/authentication failures still stop monitoring and open positions show an alert. Backend restart restores only recorded active held-position monitoring in exit-only mode; it never resumes new-entry trading.

**Discretionary manual entries:** Submit Order and chart Buy Call / Buy Put bypass RSI entry gating in PAPER and LIVE. The exact selected side/option route, quote freshness, authentication, margin and contract/order validations still apply. Filled entries are monitored with the selected RSI settings for the opposite completed crossover, without automatic reentry. Automatic Start Runner entry rules remain signal gated. Manual entries are recorded as `MANUAL_DISCRETIONARY`; their exit cursor starts at the latest completed timeframe boundary at submission, so earlier signals are not replayed. Matching backend capability `manual_discretionary_entry` is required before this behavior can be used.

### Optional ADX entry filter

The Delta indicator section includes a completed-candle Wilder ADX(14) graph below RSI, with an editable threshold line. The optional runner entry filter is off by default; the initial minimum is 25. When enabled, a fresh RSI crossover or candle-extreme EMA-touch entry additionally requires underlying ADX strictly greater than that minimum. Missing or warming-up ADX blocks entry. The selected chart timeframe supplies ADX; no forming candle is used. This applies to both option and futures runner entries, with options measured on the underlying contract.

Opposite-crossover exits, partial exits and trailing protection run before this gate. Manual Submit remains discretionary and does not use the ADX entry filter. Filter selections take effect only on an explicit new Start; editing inputs does not modify an already-running strategy. The indicator graph is a display aid and does not enable trading. ADX is a lagging strength measure and can remain high during reversals; it is not a guarantee against whipsaws. New event snapshots record ADX in their full journal context; older records are not reconstructed.

### Monitoring continuity

FYERS authentication refresh replaces only FYERS feed resources without restarting the shared server. Delta positions save their monitoring settings, candle cursor and active/intentional-stop intent. Recovery uses the held position’s symbol, timeframe and trailing settings independently of the current chart selection. Missing evidence, contract or ownership mismatches block restoration. Pending Live orders require reconciliation before restoration.

An independent watchdog and in-app alert expose inactive, stale or retrying held-position monitoring. Restore paper exit-only monitoring reconciles the saved lifecycle and scans missed completed candles for exits, using a fresh current option quote for the fill rather than a historical premium. Once flat, the recovered monitor stops without reentry or reversal. Application-managed exits require a running, connected process and are not native exchange stops.
