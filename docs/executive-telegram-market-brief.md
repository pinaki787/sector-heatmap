# Executive shared market brief

The root `sector-pulse-combined-reports.service` owns this sender. Account dashboard workers, the Auto scheduler and private notification services do not need restarting. The established shared-market destination remains unchanged. Its configured title is Sector Pulse Trade Alerts; Sector Pulse Updates is the separate private execution feed.

`market_brief_visual.py` produces one 960-pixel PNG with an executive regime, verified sector bars, ranked composite scores, rotation-state colours, and signed score changes against an earlier distinct stored completed candle in the same session within 45 minutes. No price-return or money-flow claim is made. The regime is descriptive score breadth: broad strength if at least 60% of scored sectors reach 55; defensive tilt if at least 60% fall below 45; otherwise mixed. Missing sectors remain unavailable. Composite-score history does not retain live-feed quality; the image explicitly says this. Existing sector candle and observation freshness gates remain in force.

The second section contains at most two Handoff findings, sorted by recorded conviction. Intraday and swing report-only underlying and estimated premium levels retain separate labels. Legacy reports use a labelled shared plan; no horizon is recalculated in the sender. Data timestamps are distinct from analysis-generation timestamps. Delayed broker evidence overrides an otherwise recent timestamp. Unknown states and missing levels are withheld. These are market-analysis findings, never confirmation of an order or fill. The screener footer retains bounded coverage and freshness, without changing its universe or integration with Auto.

Public output is projected from sector definitions and explicit market-only report fields. It excludes holdings, quantities, sizing, allocation, funds, private P&L, account IDs, credentials, arbitrary narratives and execution receipts. Raw report objects and private event metadata are not sent to Telegram. Existing shared/private destination checks are retained; the combined sender additionally refuses absent, disabled, private or coincident shared routes.

Caption is capped below 1024 UTF-16 units (normal observed caption ~453). Fallback text is below 3900 characters. PNG is capped at 9 MB; normal observed image ~240 KB, 960x2131. Telegram receives a single photo plus caption, with no second follow-up text post. Local rendering failure or a missing image before transmission uses the compact text event instead. A definitive photo HTTP 400 rejection allows text fallback. Integrity mismatch is withheld. Timeouts, disconnects, crashes while sending and server-error ambiguity never trigger a second message; REVIEW requires reconciliation. The existing persistent slot ID, process lock and SENDING-before-network outbox prevent blind replay. API-side exactly-once cannot be guaranteed, so uncertain outcomes stay in REVIEW.

The existing 15-minute NSE regular-session/holiday gating, late-slot suppression, receipt audit and destination activation cutoffs are unchanged. `preview` has a separate lock and returns before opening or recovering the delivery outbox; it renders saved evidence without sending or modifying delivery state. Sunday preview correctly uses Friday's last completed sector session and labels old Handoff evidence stale. No ad hoc sample or test messages are authorized by this redesign. Scheduled delivery acceptance remains a separate verification after a market-open slot.

## Sector multi-timeframe alignment (v2)

Each of the 14 strength-ranked sectors also shows its exact multi-timeframe alignment and the separate 15m, 1H, Daily and Weekly states. Full Bullish requires all four states >=1; Full Bearish requires all four <=-1. Daily/Weekly alignment with differing shorter frames retains the existing Bullish/Bearish Alignment label. Everything else follows `analysis.mtf_alignment` directly, including Mixed and Unavailable. State labels use `analysis.STATE_LABELS` (Strong Bullish, Bullish, Neutral, Bearish, Strong Bearish); the visual abbreviates Bullish/Bearish to Bull/Bear with an explicit legend. Strength score does not determine directional alignment.

The historical strength ledger does not retain per-timeframe states. A separate account-isolated, analysis-only `combined_sector_worker` therefore reuses `SectorAnalysisService` completed-candle collection/quality and `calculate_timeframe_state`. It never starts the service loop or invokes refresh/store writes, trading runners, Auto analysis or execution. Its isolated state path is under report artifacts; it cannot overwrite canonical analysis history. All four timeframe labels for all 14 sectors (56 states) were compared with the actual served dashboard and matched, along with 14/14 overall alignment labels in the saved strength history.

Scheduled collection runs inside the existing 820-second slot budget, with at most 210 seconds for the sector MTF worker and the remaining time for the original screener scan. Late-slot delivery is still suppressed. MTF failure cannot fabricate states: the image marks Unavailable/Incomplete, while retained strength scores remain independently labelled. Missing frames never become neutral; stale or unknown evidence is explicit beside alignment and marked `!` in the frame breakdown. Directional labels can remain recorded full alignment while evidence is stale; they never imply fresh execution eligibility. Open-session checks additionally reject a prior-session intraday bar and an older collector result. MTF frame timestamps and collector timestamp are shown separately from strength/Handoff times.

The compact text fallback retains sector score, score change, rotation, alignment and the four-state breakdown. The caption still remains below Telegram's limit. V2 preview was 960x3372 (~403 KB); a 390-pixel-wide inspection showed all rows/labels without clipping. The output is a long image that can be opened/zoomed in Telegram. Existing privacy projection, routes, one-event outbox, ambiguous-send behaviour, holidays and session gating are unchanged. No ad hoc Telegram post was sent for this feature. Only the combined-report sender needs restarting; trading workers and Auto remain untouched.

## Phone-readable panel delivery (v3)

V3 supersedes the single tall image. It renders three sectors per 720-pixel-wide panel, preserving all 14 sectors in five ordered panels (3/3/3/3/2), followed by up to two separate Handoff cards. The current one-finding report is six photos. These are individual ordered photos rather than an album grid, because album thumbnails would reduce text size again. Each panel is numbered. Maximum source height is 1000 pixels; at a 360x500 Telegram media bounding box, the main 28-35 pixel fonts become approximately 14-18 pixels. The old 960x3372 sheet occupied only 142x500 pixels in the same box. Local before/after previews model that constraint explicitly; no new Telegram sample has been posted for v3.

Sector cards retain exact alignment, four distinct timeframe labels and states, strength score /100, rotation, score change and source/freshness labels. Dates for each timeframe are included in the panel caption. Missing/stale evidence is explicit and not converted to neutral. Handoff has its own large entry/stop/target grid with separate spot/premium rows, estimates and stale/report-only labels. A captured selected-provider AI decision such as WAIT is shown separately from technical evidence grade. Private sizing, holdings, capital and P&L remain excluded.

A single durable report event is still created per scheduled slot. Its immutable retained panel manifest is recorded in `brief_panels`, bound to a destination hash. Each panel is marked SENDING before the HTTP request; successful Telegram acceptance stores its message ID before the next panel. Accepted panels are skipped on retries. An explicit rejection such as rate limiting can resume only unaccepted panels inside the original slot. Unknown HTTP/disconnect/5xx outcomes or restart during SENDING become REVIEW and stop the remaining set. A rejected later panel does not trigger a duplicate full-summary fallback. A local rendering failure, missing retained file before any accepted photo, or definitive first-photo HTTP400 rejection can use the compact text fallback; the selected fallback mode is durable. Integrity mismatch always withholds. Per-panel slot checks reserve the request timeout for all remaining photos; if too little time remains, the set or remaining tail is withheld rather than sent late. The same slot deadline also applies to text fallback.

Telegram cannot provide an atomic multi-message transaction or guaranteed exactly-once send. A partially accepted set can therefore remain incomplete and require review, but accepted/uncertain panels are never blindly replayed. The aggregate receipt lists accepted message IDs. Previously retained single-image events use the existing legacy delivery path. The already-authorized v2 sample (message85) is not resent. The existing shared/private routes, market calendar and schedule, source collectors, trading workers and Auto remain unchanged. Only the combined-report sender is restarted to load v3.
