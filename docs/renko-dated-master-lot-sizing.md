# Renko historical lot sizing — authoritative broker master only

Confirmed correction, 25 October 2026: historical option quantity is selected lots multiplied by the exact contract's date-applicable FYERS master lot size. Manual, default and unverified research lot-size substitutions are prohibited. No value is borrowed from today's master for a different historical date.

## Evidence and date policy

`strategies/renko_supertrend/historical_lots.py` archives immutable raw master bytes under `data/backtesting/fyers-contract-masters/objects/` and dated manifests under `manifests/`. Each manifest identifies FYERS public source URL, exchange segment, observed timestamp, snapshot date and SHA-256. Exact-contract resolution checks symbol, expiry, strike, option side, positive whole lot size, source checksum and date coverage. Conflicting, corrupt, mismatched or missing evidence withholds lot size.

Without an explicit authoritative validity declaration, snapshot coverage is conservatively the observed day only. Explicit exact-contract effective-period declarations may cover other dates: the resolver verifies their archived raw record, authority URL, checksum, symbol, expiry, lot and interval. Same-calendar-day capture is not required when this sourced coverage exists. No such explicit period declaration was found for the actual 16 October validation contract. The `effective_from`/`effective_to` audit fields describe that verified evidence boundary; they do not claim the exchange lot regime began on the snapshot day. The broker row's last-update date is retained separately. Neither that field nor an earlier/later snapshot is silently projected across historical trading dates. Broader validity requires authoritative date coverage, not an inferred lot-size rule.

The existing one-minute cron invocation of `sector_heatmap.master_cache_maintenance` now archives derivative masters when it performs its established refresh. It preserves immutable dated evidence before contracts disappear from current masters. An archival error is reported separately and does not prevent the existing live-master cache refresh. No new schedule was created.

Inspection covered current FYERS CSV caches, the preserved 12 October backup with original 11 October cache timestamp, local contract metadata and FYERS expired-contract API capabilities. Twenty-one existing derivative-master observations were retained with their timestamp basis. The historical API returns exact symbols/expiry and premium candles; it does not provide dated lot-size coverage in the responses inspected. Generic NSE lot circulars are not substituted for exact broker-master evidence.

## Calculation and report

Backtest v2 (`dated-contract-master-backtest-v2`) rejects any supplied `historical_units_per_lot` value. The normal UI no longer offers that input. Undated `contract-metadata.json` entries and an undated lot property on an expired-symbol response cannot size a trade. The report and JSON/CSV audit retain lot size, source, dated coverage, raw hash, source row and provenance. Missing coverage remains visible alongside the exact held contract and actual premium entry/exit observations; quantity, gross/net P&L and charges remain null. Full-period performance is withheld. Cash share quantity is a separate selected share count, not an option lot-size substitute.
