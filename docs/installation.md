# Portable Sector Pulse installation

Supported runtime: macOS and Linux with POSIX file locks; Windows users should use WSL2 Ubuntu. Native Windows Renko execution is not supported. Python 3.11 or 3.12 with pip/venv and Node.js 20.19+ or 22.12+ with npm/npx are required to build from Git. Internet access is required for dependency installation and broker data. Git is needed only for cloning. The release tarball includes a prebuilt UI, so Node is optional with `--skip-build`.

## Install

From GitHub:

```sh
git clone https://github.com/pinaki787/sector-heatmap.git
cd sector-heatmap
git checkout codex/renko-rsi-portable
python3.11 setup.py
```

Or extract `sector-pulse.tar.gz`, enter its `sector-pulse` directory, and run the setup script inside:

```sh
tar -xzf sector-pulse.tar.gz
cd sector-pulse
python3.11 setup.py --skip-build
```

The idempotent installer creates `.venv`, installs pinned Python dependencies, validates them, builds or verifies the UI, copies private configuration examples only when absent, creates private state storage and imports the application. It reports missing system prerequisites with installation guidance. It does not install system package managers or change existing credentials. Rerunning preserves local settings. It never starts a runner or sends orders.

On macOS, install Python with `brew install python@3.11`; on Linux, install Python 3.11/3.12 and its corresponding venv package through your distribution. Install Node from https://nodejs.org when building. No Codex app or bundled Codex runtime is required.

## Configure and launch

Edit `.fyers.env` with your own registered FYERS app ID and secret. Register `http://127.0.0.1:8080/callback` as its redirect URI. Authenticate interactively (broker login/2FA cannot be generated by the installer):

```sh
.venv/bin/python get_fyers_token.py
.venv/bin/python heatmap_server.py
```

Open http://127.0.0.1:8080 . A fresh install is stopped, has no saved positions, and has live-order gates disabled. Market data requires valid broker authentication. Select Paper and review visible settings before manually starting a strategy. Do not copy `.private`, tokens, `.env`, `.fyers.env`, journals, or account files between computers as part of deployment. Broker live-order enabling remains a separate deliberate configuration step. For an alternate port set `HEATMAP_PORT` and register/update the matching callback URL.

Renko's optional Wilder RSI14 slope filter defaults ON for new configurations: bullish requires rising RSI; bearish requires falling RSI. Flat, opposite slope, and insufficient history block entry. Explicit saved OFF remains OFF; legacy saved runs retain their original entry rules. Intrabar OFF waits for a completed host candle for entries and EMA exits; ON permits live breaches. Directional fill markers represent saved execution evidence, and the RSI/SMA overlay is a display indicator.

## Validation and archive

```sh
.venv/bin/python -m unittest discover -s strategies/renko_supertrend -t .
node --test tests/renko-*.test.cjs
python3.11 scripts/package_release.py /path/to/sector-pulse.tar.gz
```

Archive creation requires a clean committed tree, Git and a previously built UI. It packages only tracked source plus built UI, excludes local credentials and state, and records the source commit in `RELEASE_COMMIT`. Python installation and macOS startup are verified for this release; Linux/WSL support follows the POSIX implementation and still requires testing on the destination.
