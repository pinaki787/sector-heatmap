# Owned Handoff entry and exit monitoring

Explicitly authorized scope: explicitly marked FYERS Auto Analysis Handoff receipts only. Manual Handoff and unrelated positions are excluded. No Renko, unrelated/manual positions or report-only horizon projections are adopted. The exact reserved recommendation is immutable per lifecycle.

Entry: completed 15-minute close supplies the existing directional at/above or at/below trigger and 0.5% chase bound. Missing structured conditions block Auto. A durable entry queue captures the recommendation, policy revision, capital reservation and next-slot expiry. Exact cash breakouts may rest as bounded STOP-LIMIT orders (trigger and limit at the recommended exact tick); options wait for the underlying stream and submit the captured premium LIMIT, never an underlying price as a premium trigger. Final broker preflight repeats fresh condition, quote, contract, funds/margin and loss checks. No market entry is introduced. An expired wholly unfilled order is cancelled by its exact id; partial fills remain attributed and managed. Settings changes expire unsent waits. PREPARING/uncertain outcomes are retained without replay across restart.

Products: Overnight/CNC first where valid, F&O MARGIN Overnight, cash shorts Intraday. Only a fully broker-rejected original (status 5, zero fills, zero remaining quantity and no exposed/pending contract) with an exact allowlisted Intraday-only reason or structured INTRADAY_ONLY code qualifies for one correction. Unknown wording, margin/auth/liquidity failures, partial fills, accepted/pending status and timeouts never qualify. Fresh correction preflight preserves contract, direction, quantity, exact entry and accepted exits. Original and corrective attempt lineage is archived before crossing each submit boundary. Unknown real broker reason formats are withheld, not loosely parsed.

Exit: a dedicated server-side loop uses exact-held-instrument streamed LTP, maximum five-second provider and receive age. Position/order snapshots poll every two seconds; entry queue checks run in the authenticated scheduler loop. The persisted monitor heartbeat becomes stale after twelve seconds. Broker native linked exits remain primary fallback until a fresh target/SL trigger is latched. The application freezes the exact pending entry remainder, requests removal of only owned linked exits, waits for broker acknowledgement and reflected cleared/pending state, then repeats ownership and position checks before requesting exit by the single exact position id. There is no free-standing SELL or exit-all path. Position-id exit targets the broker remaining position, avoiding reverse exposure if a native exit already won. A broker-native fill during takeover is reconciled without a second exit. No mutation is blindly retried following timeout or crash. Exact parent fills, side, product, quantity and any competing orders are checked; foreign/shared exposure blocks action. Manual same-contract/product changes concurrent with the final broker RPC cannot be made atomic by this application and must be avoided.

The monitor recovers from its own durable DB without a browser session, checks owned account Live permission and feature ownership, and requires functioning FYERS broker credentials. Pausing it blocks new Handoff entries and application mutations; existing broker orders remain independent. An uncertain or stale monitor blocks new entries. Target/SL prices do not guarantee execution prices or fills. Broker exit-position acceptance, Smart cancellation visibility, market-order restrictions and overnight validity must be confirmed from real broker evidence; no live order was created to validate them. No new EOD square-off, rollover, expiry exit, trailing policy or report-horizon execution policy is introduced. Unresolved native exit removal means the app withholds a competing exit and exposes the state for review.

Flat reconciliation releases the exact reservation and records attributed gross realized P&L where exit fills are available. Unknown fees and unattributed fills withhold net P&L. Event records, active/partial/pending/uncertain states, accepted product and stop/target, entry waits, heartbeat, pause/resume and diagnostic reasons are visible in Handoff. Saved Auto authorization remains durable, but scheduler session binding is intentionally memory-only: notification-admin restart requires the owner to save the same schedule again before new entries can run. This is separate from exit monitoring of already-owned trades.

Operational handover limit: after confirmed removal of native linked exits, a rejected or unacknowledged exact-position exit can leave the held position without that broker fallback. The application exposes an attention/uncertain state and blocks new entries; it does not invent broker acceptance or send a potentially duplicate repair. Real broker lifecycle acceptance has not been validated by a test trade.
