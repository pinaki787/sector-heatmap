# Delta India Backtest workflow

Open **Delta India → Workflow → Backtest · research only**. The manual parameter grid is the default Backtest view. It is deterministic and makes no OpenAI review calls. Adaptive source and history are preserved, but its UI, scheduler and API routes are not loaded by the manual research worker. This is a separate research view within the existing workspace. It has no order submission, broker configuration, runner start, or strategy promotion actions. Research defaults and saved results are independent of trading settings. Copy current chart signal settings reads only a loaded chart’s inputs into the research draft; load a chart in Read-only analysis first if this button is disabled.

Choose BTCUSD/ETHUSD underlying perpetual futures, one or more timeframes, inclusive IST dates through yesterday, and a chronological held-out tail (10–50%). Enter comma-separated RSI lengths and RSI MA lengths, select EMA and/or SMA, and select one or both existing entry rules. RSI/MA supplies the entry signal and the opposite-crossover exit. Optional ADX(14) and prior-candle momentum filters can each run enabled or be compared off/on. Enter multiple ADX thresholds; the ADX period remains fixed at 14 and momentum lookback remains fixed at one completed candle. All enabled filters must agree with the RSI signal (AND); they do not create independent entries. Current rules reuse the deployed completed-candle RSI crossover / EMA candle-extreme touch calculations; crossover-only is also selectable. Momentum and ADX filter entries only.

The unfiltered baseline is always included once per signal configuration. Optional, **unvalidated** candidates are rising Bollinger BandWidth and squeeze release. Population-standard-deviation bands accept multiple lengths and decimal deviations. Squeeze history lengths, percentiles and release windows also accept multiple comma-separated values. Selected Bollinger modes are alternatives combined with each RSI/MA/ADX/momentum configuration. Baseline is included once per signal/filter configuration; unused squeeze parameters do not multiply baseline or rising-width experiments. Relative BandWidth expansion and percentile conditions are scale-invariant, so different deviations can yield identical trades. SMA current-rule entries equal crossover-only because EMA touch applies only to EMA smoothing. A squeeze compares the preceding width against a percentile of earlier widths, excluding the current and preceding width from that reference distribution. A release starts when that squeezed width expands; entry is permitted during the specified release window while width is rising. No future candles enter the calculation.

The grid is capped at **96 combinations**, **25,000 requested candles per timeframe**, and **2,000,000 candle-combinations**. Sequential 1,500-candle windows stay below Delta's [2,000-candle response limit](https://docs.delta.exchange/#get-historical-ohlc-candles). Public windows cache for 24 hours. Progress, downloaded/cached window counts, actual coverage, missing intervals and contiguous warmup are shown. Conflicting duplicates, missing requested candles or insufficient warmup block metrics. No interpolation or gap-spanning positions are simulated. Dates at the beginning of exchange history may need a later start to provide indicator warmup; the earliest full continuous dataset is not asserted.

Each training/held-out period starts flat. Signals use completed candles and fills use the next contiguous candle open, adjusted adversely for configured slippage and half-spread and rounded to the current product tick. Opposite completed RSI crossover exits are retained, with no same-signal reversal. Positions still held at a period boundary are forcibly closed at its final candle close with costs. Entry notional plus fees must fit equity. Quantity stays fixed. Equity/drawdown use completed-close marks; chart curves are sampled to at most roughly 1,200 points while metrics use all candles and trade history retains every fill and displays 200 trades per page.

Fees are a user-supplied allowance in basis points on each fill, including any taxes the user wishes to model. Funding is an optional constant adverse notional drag per day, **not actual historical funding**. Results use verified current contract units and tick size throughout; historical specification changes, margin, leverage, liquidation, order-book liquidity and missed/partial IOC fills are not modeled. USD figures are quote-equivalent research, without an INR conversion.

The grid ranks by **training net return**, then lower training drawdown. It shows the later chronological held-out return, trade count, drawdown and net profit factor separately. No-loss profit factor is reported as unavailable with a descriptive basis, never an invented finite number. Inspect any combination for its period metrics, equity/drawdown and trades; download the selected full research result as JSON. The last completed run survives worker restart. Repeatedly checking held-out results can overfit them; an optimized winner is not validated.

This is **underlying futures research, not ATM-options P&L**. Historical option chains, strike/expiry selection, premiums and spreads have not been established. Option-premium trailing is excluded; no changes are made to the deployed execution strategy.

## Local research worker

The public-data worker runs separately on loopback port 8086 to avoid restarting an active trading server. Normal app startup calls `ensure_research_worker()` and reuses a correctly identified existing worker. An occupied port is left untouched. The dashboard accesses only its research routes; cross-origin access is restricted to the local dashboard on port 8080. The worker accepts only BTCUSD/ETHUSD public metadata and historical candles and does not load trading credentials or execution ledgers.

If needed, start it from the repository with:

```sh
.venv/bin/python -u -m sector_heatmap.delta_backtest_server
```

Public cache and the last completed result are under `.private/delta-backtest/`; logs are in `output/delta-backtest-worker.log`. Neither research jobs nor research cancellation stop a broker runner. Losing the worker during a job requires a rerun; completed windows are reusable from cache.

## Archived adaptive research agent

**Disabled in the current manual workflow.** The following describes the preserved implementation, not currently available controls. Research loop state is stopped and AI reviews are disabled. Re-enabling it would require a separate explicit request; no paid model requests are needed for manual grids.

Within **Delta India → Backtest → Adaptive research agent**, save research-only settings, run one bounded cycle, or explicitly start/stop the persisted cadence. A fresh installation starts with the loop stopped. The isolated public-data worker on 8086 never invokes an order endpoint or mutates the trading runner.

The agent updates completed candles with gap/conflict/warmup checks. Past ADX and EMA identify trend/range; ATR-percent is compared with earlier volatility observations. Up to 24 bounded RSI/MA/Bollinger combinations are searched deterministically, with at most 12 chronological validation folds per cycle. No ML model is fitted. Training score is net return minus half maximum drawdown and a quarter of fee turnover as percent of initial capital. Eligibility requires minimum training/validation trades, at least three earlier matching-regime validation windows, and at least 60% positive windows. Real-time selection persists its incumbent, challenger count and cooldown; unchanged decision timestamps do not advance persistence.

Each historical validation fold starts flat, uses fixed contracts and fresh starting capital, and closes at its end. Aggregate P&L sums independent folds; it is not a continuously invested portfolio. The RSI14/EMA14 fixed baseline shares the other configured entry gates and costs. Prospective paper windows freeze exact settings and contract units/tick before their future start and are reported separately. Promotion proposals require eligible regime evidence, at least 20 positive-net prospective trades and a positive one-shot final holdout of at least 10 trades. Even then the status means **futures review ready**, never permission for execution or evidence for ATM options.

The first cycle permanently seals the latest configured final-holdout bars. Those bars are excluded from optimization, regime features and AI inputs, even after an optional one-shot evaluation. While later unsealed data lacks enough history, selection remains based on the pre-holdout segment; the UI shows both fetch time and optimization time. One candidate is durably frozen before final scoring; a failed read may retry that candidate only. Scored final data cannot be reranked. Changes to symbol/timeframe/holdout size are blocked after sealing.

An existing authorized `OPENAI_API_KEY` is read privately from the worker environment or workspace `.env.local`; no credential is copied into research state, browser storage or exports. OpenAI Responses uses `store:false`, no tools, capped output and one aggregate review per meaningful cycle. The model can explain results and propose at most two bounded experiments; the user explicitly adds them to the research grid. It cannot select live trades. Defaults are two calls/day, 12,000 conservative token reservations/day and 400 output tokens/call, reset at midnight IST. Reservations use UTF-8 input/instruction bytes plus framing and output allowance and are persisted before every attempt; failed attempts retain the charge and do not retry automatically. Provider-reported token usage is shown separately. Reviews cache by model and exact aggregate evidence. Missing keys, errors or budget exhaustion leave deterministic research available and are displayed honestly.

State, candidate evidence, cycle history and usage live under `.private/delta-backtest/adaptive/` with owner-only state files. Exports include exact signal settings, simulation costs, product identity, evidence, holdout state and execution limitations.
