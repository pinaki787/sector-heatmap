Sector Pulse user guide

Connect your broker, configure a strategy, and track its server-managed runner. A chart signal, an accepted order, and a confirmed fill are separate events.

Accounts and access

Open Configuration → Brokers to manage saved connections. Connection Settings edits the selected account; Test Connection checks current access; Open Dashboard opens that account's workspace. A connected account does not guarantee that every market-data permission is available.

Use Connect to renew an expired session. Dhan may require an interactive browser sign-in. Saved keys remain separate from temporary access tokens. User Master is available only to administrators. Runners and account data belong to the signed-in user's accounts.

Runner jobs

  1. Open Runner jobs in the sidebar. The default list shows active runners and jobs with a retained position or pending order.
  2. Use Open settings & chart to return to the selected account and runner. Opening it does not start it.
  3. Select individual jobs, or Select all active, then Stop selected jobs. Results are reported separately for each job.
  4. Stopping is not proof that an exit filled. Renko's existing stop flow requests closing owned positions and reconciling pending orders; legacy strategies can stop monitoring without closing. Check the selected strategy and broker orderbook.
  5. Enable Show stopped / saved jobs to inspect inactive instances. Submission history, where supplied by the loaded backend, retains separate run records. Older runs are not reconstructed from chart arrows.

Strategies run on the server. Closing a browser does not stop them. Another device signed into the same user can read the same account-bound inventory.

Renko strategy settings

Choose the broker account, its instrument, timeframe, Paper or Live mode, and size before Start. Live mode can submit real orders. A form edit is not proof that the active runner adopted it; check the applied runner settings.

  • Manual brick size: remains fixed across chart timeframes. Session-based calculation uses the instrument's configured reference window and ATR settings.
  • Higher timeframe: one-minute host defaults to five-minute confirmation; five-minute host defaults to fifteen-minute confirmation. The confirmation timeframe must be higher when enabled.
  • RSI Between: minimum and maximum are inclusive. The RSI slope filter is a separate condition.
  • EMA10 retest: offers an additional pullback entry path; other enabled entry checks still apply.
  • Exit section switches: disable that exit family while retaining its subordinate selections for re-enabling. Entry and chart controls are separate.
  • Quick-loss / sideways lock: after a qualifying quick losing exit, new entries wait for a breakout from the recorded underlying range. Unknown net costs can also trigger a protective lock.

Charts and assessments

Use the section shortcuts for Trade setup, Entry rules, Exit rules, and Chart. The candlestick height slider and divider resize the price panel; the vertical scrollbar reaches RSI and other studies. The compact assessment row expands one panel below it.

Host candles are broker OHLC. Synthetic Renko bodies are calculated bricks. A historical signal does not prove an order was submitted. Check recorded runner assessment and order evidence for the actual decision.

Orders and profit or loss

Order acknowledgement, partial fill, full fill, cancellation, and unresolved submission are distinct states. Do not assume an accepted ticket is a filled position. A timeout after submission needs reconciliation before another submission.

Runner jobs display net P&L after estimated costs when the runner supplies it, in the reported currency. This is an estimate, not the broker contract note. Missing fees, funding, fills, or executable valuation can leave net P&L unavailable; gross P&L must not be substituted silently.

FYERS REST quote tt marks the trading-day start. It is not a last-price-update timestamp. Receipt time shows when the request completed, not proof of an exchange-price update.

Troubleshooting

  • Session expired: open the same saved account's Connection Settings and authorize again; test the renewed connection.
  • Feed delayed: compare the selected account, symbol, and tick state. A fresh runner heartbeat does not prove fresh prices or complete candles.
  • Start blocked: read the displayed reason. Missing history, unsupported settings, account validation, exposure, or risk checks may prevent activation.
  • Stop requested: wait for the actual terminal state and broker reconciliation. Do not repeatedly submit stop or exit orders based only on a slow page.
  • Jobs unavailable: the inventory names failed sources. A partial inventory does not mean those runners stopped.
